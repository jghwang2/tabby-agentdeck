설치와 첫 실행

  1. Tabby의 설정 → 플러그인에서 agentdeck을 찾아 설치하고 Tabby를 재시작한다.
  2. 설정 → AgentDeck에서 작업 루트를 지정한다. 추가 작업 루트 프로필에 이름과 폴더를 저장하면 여러 프로젝트를 선택해 열 수 있다.
  3. + 새 탭 또는 Ctrl+T로 탭을 연다. 작업 루트가 하나면 바로 열리고, 여러 개면 선택한다. 터미널에서 사용할 에이전트 CLI를 실행한다.
  4. 더 정확한 상태와 세션 연결을 위해 설정에서 사용하는 에이전트의 상태 통보 훅을 설치한다. 통신이 필요하면 메시지 연결 안내도 확인한다.

Windows에서 검증했다. 새 버전 안내가 나오면 업데이트 여부를 선택한다. 변경 내용은 전체 변경 이력에서 확인한다.

01한눈에 보기

화면은 두 덩이다. 왼쪽은 터미널, 오른쪽은 세션 목록(사이드바). Tabby 순정 탭바는 감추고 이 사이드바가 탭 관리를 대신한다 — 탭이 여러 개일 때 가로 탭바로는 "무슨 작업인지" 를 담을 자리가 없기 때문이다.

터미널 폭은 창 높이에서 4:3 비율로 역산해 고정한다. 창을 아무리 넓혀도 터미널이 옆으로 늘어나지 않으므로, TUI 가 그리는 상자와 줄바꿈이 창 크기에 따라 흔들리지 않는다. 남는 폭은 사이드바가 갖고, 그러고도 남으면 터미널이 흡수한다.

02작업 상태

각 세션이 지금 어떤 상태인지 6가지로 표시한다.

표시뜻언제
● 진행중에이전트가 일하고 있다출력이 계속 나오는 중
⏸ 승인대기사람을 기다린다도구 사용 허가를 물어봄
⛔ 한도 도달사용량 한도에 걸렸다언제 풀리는지도 함께
✔ 완료작업이 끝났다응답을 마치고 멈춤
✘ 오류실패했다오류 문구가 나옴
○ 대기아무 일도 안 한다일정 시간 출력 없음

승인대기에는 무엇을 승인해야 하는지가 같이 붙는다. 위 그림의 두 번째 줄이 ⏸ 승인대기 · Claude needs your permission to use Bash 로 나오는 것이 그 예다. 창을 여러 개 띄워 놓고 다른 일을 하다 돌아왔을 때, 어느 세션이 왜 멈춰 있는지 눌러 보지 않고 안다.

상태를 직접 지정하기

상태는 훅을 설치하지 않아도 화면에 찍힌 문구로 판정한다. 그래서 Claude Code 뿐 아니라 Codex · Gemini 도 같이 동작한다. 훅(설정 창에서 한 번 설치)을 넣으면 에이전트가 직접 알려주므로 더 정확해지지만, 없어도 쓸 수 있게 만들어 두었다.

03세션 그룹

세션을 작업 폴더(프로젝트) 단위로 묶는다. 위 그림의 api-server tools web-client 이 그것이고, 헤더 옆 숫자는 그 그룹의 세션 수다. 헤더를 누르면 접힌다.

묶는 기준은 탭이 태어난 작업 폴더다 — 셸에서 cd 를 해도 그룹이 안 바뀐다. 세션이 사는 동안 소속이 흔들리면 "방금 그 줄이 어디 갔지" 가 되기 때문이다. 그룹이 하나뿐이면 헤더를 아예 그리지 않으므로, 한 프로젝트만 쓸 때는 화면이 예전과 같다.

04검색과 필터

사이드바 맨 위 검색창에 치면 제목 · 작업 이름 · 작업 폴더를 한 번에 좁힌다. 상태 칩(⏸1 ●1 …)을 누르면 그 상태만 남는다.

접힌 그룹에 결과가 있으면 임시로 펴진다. 그러지 않으면 "검색했는데 아무것도 없다" 로 보이기 때문이다. 검색을 지우면 원래 접힌 상태로 돌아간다 — 접기/펴기 설정 자체를 건드리지 않는다.

05키보드로 다루기

Ctrl+L 로 목록에 들어가면 마우스 없이 훑을 수 있다.

키하는 일
↑ ↓줄 사이 이동. 활성 탭은 바뀌지 않는다
Home End첫 줄 / 마지막 줄
Enter그 세션으로 옮긴다. 그룹 헤더면 접기/펴기
Esc검색·필터가 있으면 먼저 그것을 지운다. 없으면 터미널로 복귀
Tab검색창으로
포커스와 선택을 일부러 갈랐다. 줄을 지날 때마다 탭이 바뀌면 그 탭의 출력이 화면을 덮고 터미널 폭이 매번 다시 적용되어 화면이 튄다. 그러면 "어느 세션이었나" 를 훑어보는 것 자체가 불가능해진다. 그래서 ↑↓ 는 테두리만 옮기고, 실제로 여는 것은 Enter 하나다.

검색창의 ↑ 는 일부러 가로채지 않는다 — 한 줄 입력에서 그 키는 커서를 맨 앞으로 보내는 편집 동작이고, 치던 검색어를 고칠 때 실제로 쓴다.

06별명·순서·탭 편집

탭 제목과 별명은 별개다. 별명은 작업 프로젝트를 바탕으로 자동 배정하며 열린 동안 유지한다. 탭을 닫으면 그 번호를 새 탭이 가장 작은 번호부터 재사용한다. 원하는 이름은 편집 팝업에서 지정한다.

줄을 드래그해 순서를 바꾼다. Ctrl+1~9는 현재 보이는 순서의 1~9번째 탭으로 이동하며 별명에 붙은 숫자를 뜻하지 않는다. 탭 생성에는 9개 제한이 없고, 10번째 이후는 목록을 스크롤해 선택한다.

우클릭 → 편집

  1. 사이드바의 대상 줄을 우클릭하고 편집을 선택한다. 제목이나 작업 이름을 더블클릭해도 열린다.
  2. 아래 항목 중 필요한 값을 바꾼다. 입력 중에는 아직 적용되지 않는다.
  3. 저장으로 함께 반영한다. 취소 또는 Esc로 변경을 버린다. 중복 별명이나 잘못된 건수는 고친 뒤 다시 저장한다.
항목쓰는 방법
탭 제목탭을 알아볼 제목. 최대 160자.
별명에이전트를 구분할 이름. 최대 40자이며 다른 열린 탭과 중복할 수 없다.
작업 이름현재 하는 일의 설명. 최대 500자.
상태진행중·승인대기 등의 표시를 직접 지정하거나 자동 감지를 선택한다. 표시를 바꿔도 에이전트 작업을 실행하거나 중단하지는 않는다.
예약 건수자동 집계를 끄면 0~999999의 정수를 입력할 수 있다. 실제 예약을 만들거나 취소하는 기능은 아니다.

제목·별명·수동 예약 건수는 리로드 후에도 유지한다. 편집 중 도착한 자동 갱신은 해당 항목을 직접 수정하지 않았다면 보존한다.

07결과물 미리보기

에이전트가 만든 문서·이미지·표·코드를 터미널 옆에서 그대로 본다. 화면에 찍힌 파일 경로를 스스로 주워 띄우므로, 따로 열라고 시키지 않아도 된다.

무엇어떻게
파일 끌어다 놓기패널에 놓으면 열린다. 터미널 위에 놓으면 「패널에 띄우기 / 경로 붙여넣기」를 물어본다
고쳐 저장✎ 로 편집, Ctrl+S 로 저장. BOM·개행을 원본대로 되돌린다
찾기Ctrl+F
새 파일＋ 에 없는 경로를 넣고 Enter 두 번 — 만들고 편집으로 들어간다
닫아 두고 일하다 열면그때까지 건드린 파일이 칩으로 쌓여 있고 본문은 가장 최근 파일이다 (변경 을 보고 있었으면 diff 를 다시 읽는다) — 설정 → 미리보기 패널 → 문서 패널에 읽어두기(기본 켬)
저절로 열리게 하려면설정 → 미리보기 패널 → 패널 자동으로 열기 를 켠다 (기본 꺼짐 — 여닫기는 사람 몫). 읽어두기 를 끄면 아무것도 자동으로 하지 않는다
탭마다 따로 기억한다. 세션을 옮기면 그 세션이 마지막으로 보던 파일로 본문이 바뀐다 — 옆에 남의 세션 문서가 떠 있는 채로 그것을 지금 세션 결과물이라고 착각하는 것을 막기 위해서다.

08변경 보기와 커밋

같은 패널의 변경 탭이 그 세션 작업 폴더의 git diff 를 보여준다. 누가 고쳤는지와 무관하다 — 에이전트가 고친 것이든 사람이 고친 것이든 작업트리 상태를 그대로 본다.

무엇어떻게
스테이지파일 왼쪽 딱지를 누르면 git add / 취소
커밋메시지를 적고 커밋 — 두 번 눌러야 실행된다(첫 누름은 확인)
파일:라인 참조diff 줄을 누르면 그 위치가 터미널에 입력된다. Shift+클릭 = 범위
줄을 눌러 위치를 넣는 것이 이 패널에서 가장 자주 쓰는 기능이다. "이 줄 고쳐" 를 말하려면 파일명과 줄번호를 손으로 타이핑해야 했는데, 그 왕복을 없앤다. 커밋을 두 번 누르게 한 것은 실수로 커밋되는 것을 막기 위해서다.

12문제가 생기면

화면이 깨졌을 때

TUI 가 깨져 보이면 사이드바 ↻ 를 누른다(또는 줄 우클릭 → 화면 복구). 지우고 다시 그리게 한다. 설정에서 자동 복구를 켜면 깨짐을 감지해 알아서 처리한다.

신고할 때

설정 → 문제 신고 → 모으기 를 누르면 진단 파일 묶음(zip)이 만들어진다. 버전·환경·설정·예외 기록이 들어간다. 터미널에 찍힌 내용은 기본적으로 빠진다 — 코드가 그대로 들어가는 파일이라, 보내는 사람이 명시적으로 켤 때만 담는다. 그 zip 을 GitHub 이슈에 붙이면 된다.

새 탭이 열리지 않을 때

Tabby 1.0.235 에는 지난 탭 복원과 얽힌 문제가 있다. 설정에서 기동 시 탭 복원 끄기를 켜면 해결된다 — 복원되는 건 셸뿐이고 그 안의 에이전트 세션은 이미 죽어 있어 어차피 의미가 없다.

13예약 작업 표시

예약이 있으면 해당 탭에 예약된 작업 N건이 표시된다. 자동 집계는 연결된 Claude 세션의 성공한 예약 생성·삭제·목록 조회·실행 기록을 읽는다. 일회성 예약은 실행 후 목록에서 빠지고 반복 예약은 남는다. 분할 탭에서는 그 탭에 연결된 세션만 합산한다.

다른 예약 도구나 기록이 없는 예약은 자동으로 확인할 수 없다. 이때 우클릭 → 편집에서 자동 집계를 끄고 건수를 직접 적는다. 실제 예약 변경은 예약을 만든 에이전트나 도구에 요청해야 한다. 이후 새 예약 이벤트가 확인되면 자동 집계로 돌아온다.

예약이 남은 탭을 닫으면 확인창이 뜬다. 표시 건수를 수동으로 0으로 바꿔도 실제 예약이 확인되면 닫기 확인은 유지된다. 서브에이전트 수 ❖N와 예약 건수는 서로 다른 값이다.

14에이전트끼리 메시지 주고받기

  1. 참여 세션에 상태 훅과 메시지함 등록을 준비한다. 연결 안내에 MCP 설정과 MCP 없이 쓰는 CLI 경로가 있다. 외부 터미널의 등록된 에이전트도 세션 ID로 참여할 수 있다.
  2. 화면의 별명을 보고 에이전트에게 “이 별명의 탭에 조사 결과를 보내줘”라고 요청한다. 에이전트는 최신 목록에서 정확한 세션 ID를 확인해 보낸다.
  3. 상대의 답장이나 수신 확인을 확인한다. 전송 대기함에 들어간 것과 상대가 읽은 것은 다르다.

탭이 보인다는 것만으로 통신 준비가 끝난 것은 아니다. 수신 알림을 켜면 입력 가능한 대기·완료 탭에 안내를 넣으며, 작업·타이핑·한글 조합 중에는 기다린다. 알림 입력 성공도 수신 확인은 아니다. 수신 알림 설정을 참고한다.

15지난 대화 검색·이어받기

  1. 지난 세션을 펼치고 전용 검색창에 함수명·오류코드·파일명·세션 ID 등을 입력한다.
  2. 저장된 Claude·Codex 질문과 답변에서 일치하는 결과를 선택해 내용을 미리 본다.
  3. 이어서 대화로 해당 대화를 재개한다.

현재 열린 탭 검색과는 별도다. 대소문자를 구분하지 않고 입력 문자열 그대로 찾으며, 도구 출력·시스템 안내는 제외한다. 검색은 로컬에서 실행하므로 Node.js가 PATH에 있어야 한다. MCP 연결이나 AI 요청은 필요 없다. 검색 범위와 저장 안내.

16계정·저장 위치·추가 안내

계정 관리

사이드바 아래 계정명을 누르면 현재 탭과 같은 서비스의 계정이 나온다. +에서 이름과 전체 이메일 등을 입력해 추가한다. 처음 로그인하거나 인증이 만료되면 브라우저에서 선택한 계정의 로그인과 연결 승인을 마친다. 목록에서 삭제해도 실행 중인 CLI가 로그아웃되지는 않는다. 계정 전환·저장 방식 전체 안내.

저장 위치와 작업 폴더

설정 → AgentDeck → 저장 경로에서 계정·Claude·Codex 데이터 폴더를 정한다. 경로 변경은 Tabby 재시작 후 적용되며 기존 파일은 자동 이동하지 않는다. 기록을 유지하려면 세션을 종료하고 기존 데이터를 새 폴더에 복사한 뒤 재시작한다. 저장 위치 변경 절차.

새 탭의 시작 폴더는 작업 루트 프로필에서 정한다. 프로필 삭제는 열린 탭을 닫지 않는다. Windows 창 자체는 상단 제목 표시줄로 이동한다. 작업 루트와 창 이동.

전체 설정값은 전체 레퍼런스, 버전별 변경 사항은 전체 변경 이력과 GitHub Releases에서 확인한다.
