# Ctrl+R 지연 조사 — 2026-09-23

## 결론

AgentDeck 승인 문구 판별 정규식의 과도한 역추적으로 UI 스레드가 수십 초 멈추는 결함을 격리 Tabby에서 재현했다. Codex 실행 없이 재현되었다. 실사용에서 발생한 정확한 출력 바이트는 수집하지 않았으므로, 해당 시점의 지연이 전부 이 결함이라는 단정은 하지 않는다.

## 원인 및 수정 위치

- `src/agents.ts:245`의 `CODEX_APPROVAL_PATTERNS` 두 번째 정규식은 `^\s*[›>]?\s*\d+`로 시작한다. 선택적인 표시 문자가 없으면 두 공백 반복이 같은 입력을 나눠 소비한다. `\s`가 줄바꿈까지 포함하고 multiline 모드여서, 공백으로 채워진 여러 줄에서 탐색량이 급증한다.
- `src/detect.ts:162` 부근에서 ANSI를 제거한 출력 전체를 검사한다. 같은 승인 패턴은 waitingPatterns에도 포함되며, 출력 구독 경로가 중복되어 아래 격리 시험에서 한 덩어리에 4회 검사됐다.
- `src/deck.service.ts:837`의 Ctrl+R은 `repair('all')`을 호출하고, `:1457`, `:4027`의 재그리기 경로가 터미널 폭을 줄였다 복원한다. 이때 에이전트가 출력하는 재그리기 데이터가 위 판별 경로를 통과한다.
- 수정 후보: 공백을 줄 내부의 스페이스/탭으로 제한하고, 두 번째 공백 반복은 실제 선택 표시 문자 뒤에서만 허용한다. 검증 후보는 `.tmp/repair-regex-compare.cjs`에 기록했다.
