# 저장 경로 설정

`설정 → AgentDeck → 저장 경로`에서 다음 경로를 지정한다.

- **계정 데이터 폴더**: `accounts.json` 및 `accounts/<계정키>` 아래 계정별 로그인 정보.
- **Claude 데이터 폴더**: 공유 대화 기록(`projects`), 설정, 스킬의 기본 폴더.
- **Codex 데이터 폴더**: 공유 대화 기록(`sessions`, `archived_sessions`), 설정, 스킬의 기본 폴더.
- 바로 아래 **작업 루트 프로필**: 새 작업 탭의 시작 폴더. 작성한 코드와 문서는 이 작업 폴더 및 에이전트에게 지정한 경로에 저장한다.

폴더를 직접 입력하고 입력란을 벗어나거나 **찾아보기**로 선택하면 자동 저장한다. 입력 중 다른 설정 화면으로 이동해도 저장을 시도한다. **기본값 사용**도 즉시 저장한다. 저장에 실패하면 입력값과 오류를 화면 재진입 후에도 유지하며, **경로 저장**으로 재시도할 수 있다. 빈칸에는 `기본값:` 안내를 표시한다. 저장 경로는 Tabby를 다시 시작하면 적용되고, 작업 폴더 설정은 새 탭부터 적용된다. 터미널 프로필에 명시한 `CLAUDE_CONFIG_DIR`/`CODEX_HOME`은 공유 기본값보다 우선한다. 계정을 선택한 탭은 계정별 로그인 폴더를 사용한다.

기존 파일은 자동 이동하지 않는다. 계정과 기록을 유지하려면 모든 에이전트 세션을 종료하고 기존 폴더의 내용을 각 새 폴더로 복사한 후 다시 시작한다. 계정 폴더의 대화 기록 연결은 다음 계정 준비 때 새 공유 경로로 연결한다. 연결 대신 실제 기록 폴더가 들어 있으면 덮어쓰지 않고 이동이 필요하다는 오류를 표시한다. 기존 작업 파일도 자동 이동하지 않는다.

## 검증

### Windows 사용자 환경변수 연동

경로를 저장하면 `CLAUDE_CONFIG_DIR`와 `CODEX_HOME`을 Windows 사용자 환경변수에도 함께 저장한다. 기본값 복원은 두 사용자 환경변수의 재정의를 제거한다. 환경변수 저장 실패 시 설정 파일을 변경하지 않고 오류를 표시하며, 설정 파일 저장 실패 시 이전 환경변수를 복원한다. 실행 중인 에이전트의 환경은 바뀌지 않으므로 Tabby와 에이전트를 완전히 종료하고 다시 실행한다.

- `src/storageEnvironment.ts`: 사용자 레지스트리 저장, 환경 변경 알림, 새 자식 프로세스 환경 및 실패 복원.
- `test/storageSettings.cjs`: 설정 실패의 환경변수 복원, 환경변수 실패의 설정 보존을 포함한다.
- `tools/probe-storage-environment.js`: 격리 앱 UI에서 두 값 동시 저장, 자식 프로세스 환경, 설정 실패 복원, 레지스트리 실패, 기본값 복원 7개 검사 통과. 실제 사용자 환경변수와 분리한 테스트 레지스트리 키를 사용하고 삭제했다.
- `npm test`, `npm run typecheck` 통과. 격리 UI 기본 회귀 39개 중 31개 통과, 실패 0, 환경 조건/외부 검사 항목 8개 제외. 최초 작은 창의 레이아웃 실패는 1700×1050 테스트 창에서 재검증했다.
- 검증본과 배포본 SHA-256 일치: `146E217572CAFF85C57DDA8DE5D449E60A249D9D76B739231858A9B35E41669F`. 실사용 리로드 `2026-09-23T06:29:01.945Z` 시작, `06:29:05.662Z reload restored tabs=3 dead=0 ms=1858` 완료.

- `npm run test:storage`: 기본 경로, 잘못된 경로, 계정 저장/조회, 대화 파일 쓰기, 연결 변경, 원본 보존, 프로필 경로 우선순위.
- `tools/probe-storage.js`: 격리 앱의 AgentDeck 설정 탭에서 입력 검증·저장·디스크 반영·작업 폴더 프로필 갱신을 검사한다. `node tools/cdp.js <포트> tools/probe-storage.js`.
- 격리 앱에서 저장 후 리로드하고 새 탭을 열어 실제 셸의 두 환경변수와 작업 디렉터리, 작업 폴더에 생성된 파일까지 확인했다.
- 기본 설정은 바꾸지 않으며, 실사용 데이터 이동과 계정 인증은 이 변경의 검증 과정에서 실행하지 않는다.

### 입력값이 초기화되는 문제 수정

이전 구현은 폴더 선택과 입력을 컴포넌트 내부 임시값에만 반영했다. 별도 저장 버튼을 누르기 전에 설정 화면을 닫으면 컴포넌트가 해제되고, 다음 진입 때 저장된 빈값을 읽어 기본 C 경로가 다시 표시됐다. `pickStorage`도 작업 폴더의 `pickCwd`와 달리 저장을 호출하지 않았다. 사용자 화면에서 어떤 클릭 순서가 있었는지는 기록되지 않았으므로 개별 사건의 저장 버튼 클릭 여부는 확정할 수 없다.

수정 후 입력 완료·폴더 선택·화면 이동·기본값 복원 시 자동 저장한다. 저장 요청은 직렬 처리하여 이전 저장 완료가 새 입력을 덮지 않게 했다. 오류가 발생하면 디스크에 저장된 값을 유지하면서 입력 초안과 오류를 별도로 보존한다. 실사용에서 사용자가 입력했던 새 경로는 확인되지 않아 임의로 복원하지 않았다.

- `test/storageSettings.cjs`: 화면 종료 저장, 저장값 재로딩, 저장 실패 시 초안 유지와 재시도, 유효성 오류 유지, 연속 저장 순서 검증.
- `tools/probe-storage-autosave.js`: 실제 설정 화면에서 저장 버튼 없는 입력 저장, 설정 화면을 나갔다 들어오기, 강제로 발생시킨 저장 실패 후 입력값 보존과 재시도 검증.
- 자동 저장 수정 검증: `test:storage`, `typecheck`, `test:existing`, 격리 UI 자동 저장·기존 저장 검사 통과. 격리 앱 재시작 후 경로 유지, 새 탭 환경변수 적용 및 실제 파일 쓰기를 확인했다.
- 검증본과 배포본 SHA-256: `CD148048D4363C4F3C31F268BEB16CCED81384AFF18AF5CC2D847DED30A435B5`. 기존 실사용 번들을 기준으로 수정하여 다른 작업의 배포 내용을 보존했다.
