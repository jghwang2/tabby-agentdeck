# 병렬 라운드 기록 (orchestrate)

메인이 소유하는 파일이다. 서브에이전트는 여기에 쓰지 않는다(동시쓰기 충돌 방지).
왜 남기나 — 라운드가 중간에 끊기면 "어느 유닛이 어디까지 했는지" 를 다음 세션이 알 방법이 없다.

### 유닛 B 에 넘긴 확정 기전 (메인이 코드로 확인)

`node_modules/tabby-terminal/dist/index.js` 오프셋 2986967 부근 CompositionHelper —
`keydown()` 은 조합 중이면 `_finalizeComposition(false)` = **동기 전송**, `compositionend()` 는
`_finalizeComposition(true)` = **`setTimeout(…,0)` 비동기 전송**. 그 비동기 전송이 예약된 순간
(`_isSendingComposition === true`) 누가 pty 에 바이트를 직접 쓰면 그 바이트가 먼저 나가고
음절이 한 틱 뒤에 붙는다 → "조합 음절이 커서를 따라간다". 방향키가 멀쩡한 이유는 xterm 키 경로를
타서 동기 확정이 먼저 걸리기 때문.

0.3.0 의 대책(`releaseHomeEndHotkey`)은 실사용 config 에 이미 반영돼 있는데도 재발했다
(`%APPDATA%\tabby\config.yaml:71-72` = `home: []` / `end: []`). 그래서 이번엔 핫키 소유권이 아니라
**보내기 직전에 조합을 동기 확정하거나 우리 전송을 한 틱 미루는 공통 계층**으로 잡는다.
