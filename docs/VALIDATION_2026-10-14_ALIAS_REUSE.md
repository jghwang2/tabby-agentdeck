# 닫힌 탭의 별명 번호 재사용

## 변경

- 기준: `v1.2.7` / `5d9b2e5`.
- 열린 탭의 식별자 집합으로 별명 예약을 정리한다. 닫힌 탭의 번호는 새 탭이 가장 작은 번호부터 재사용한다.
- 열린 탭은 번호·제목·화면 순서가 달라져도 기존 별명을 유지한다. 통신 주소는 계속 실제 세션 ID다.
- 재시작·리로드 도중에는 기존 예약을 보호한다. 복원 완료와 모든 터미널 프로필 준비를 확인한 다음 정리한다.
- 과거에 누적된 예약도 같은 경로로 정리하며, 현재 열려 있는 큰 번호를 강제로 바꾸지는 않는다.

## 검증

- `npm run test:sessions`, `npm test`: 종료 코드 0.
- 단위 검사: 가장 작은 빈 번호, 기존 번호 유지, 멱등 호출, 닫았던 식별자 재개, 저장·복원, 1,000회 생성·종료 반복과 예약 개수 제한.
- 별도 staging 릴리스 빌드 후 실제 격리 앱에서 별명 검사 11개와 재사용·리로드 검사 9개 통과.
- 중간 탭 종료 후 `1, 3, 2` 순서로 번호 재사용. 반복 종료·생성 3회 동일 결과.
- 리로드 전후 별명과 PTY ID 3개 모두 동일. 저장된 설정에서 닫힌 예약 제거 확인.
- 기존 회귀 러너: 176개 중 166개 통과, 실패 0개, 10개 건너뜀. 별도로 완료한 빌드·단위 검사 2개, 이미지/텍스트 클립보드와 실제 Claude 세션 등의 환경 조건 및 성능 수치 전용 항목이 포함된다. 건너뛴 항목을 통과로 간주하지 않는다.
- 검증한 번들 SHA-256: `7001485F9B45D03A8D71C94E4917F17C7BFFBBF09AD042717835C4E4D9829A46`.

## 설치와 한계

- 동일 번들 및 선언 파일을 실사용 설치 폴더에 반영하고 해시 일치를 확인했다.
- 실사용 설치 폴더를 직접 로드하는 새 격리 앱에서도 11개 검사 통과. `E1`, `E2`, `E3` 배정과 종료된 `E3`의 재사용을 확인했다.
- 변경 전 파일은 작업 폴더의 `installed-backup-20261014-225530`에 보존했다.
- 실행 중인 실사용 앱은 원격 디버깅 포트와 개발용 핫리로드가 없으므로 현재 창에 즉시 적용하지 못했다. 설치 파일 교체와 현재 실행 코드 변경을 구분한다.
- 기존 세션을 종료하지 않았다. 실사용 앱의 다음 시작 때 새 번들이 로드된다.
- 위 검증은 로컬 패치 설치 기준이며, npm 공식 배포와는 별개다.

증거는 로컬 검증 작업 폴더의 `identity-ui.json`, `reuse-ui.json`, `unit.log`, `deployment.json`, `tabby-agentdeck-test-regression/report/regression.json`에 보존한다. 원본 로그와 세션 데이터는 저장소에 포함하지 않는다.
