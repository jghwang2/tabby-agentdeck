# 회귀 체크리스트 (agentdeck)

한 곳을 고치면 다른 곳이 깨지는 일이 반복돼서, **매 수정 후 이 목록을 전부 통과해야 완료**로 본다.
눈으로 보고 판정하지 않는다 — CDP 로 xterm 버퍼와 pty 폭을 **실제 값으로 읽어** 판정한다.

## 전수 실행 (한 명령)

```powershell
powershell -ExecutionPolicy Bypass -File tools/run-all.ps1
```

아래 R1~R80 을 전부 돌리고 한 리포트로 합친다. **맨 앞에서 `npm run build` 를 돌린다(B0)** —
빌드를 빼면 회귀가 낡은 `dist/` 를 재고, "고쳤는데 그대로 FAIL" 이 나온다(2026-09-08 실측 2회).
인스턴스 기동·창 리사이즈·재기동·훅 실발화까지 러너가 한다. 실패가 있으면 종료코드 1.
사용법·판정 기준은 `tools/README.md`.

**2026-09-09 실행: total 100 / PASS 95 / FAIL 0 / SKIP 5.**

남은 SKIP 은 환경·비용 제약이다 — R6·IN6(격리 환경에서 클립보드에 이미지를 넣을 수 없다) ·
LY3(창이 작아 화면비 갈래를 못 만듦) 계열.

> **불안정한 판의 실패 목록을 그대로 믿지 말 것.** 직전 기록은 `FAIL 11` 이었는데, 그것은 다른
> 세션이 같은 저장소를 편집하는 중에 돌린 판의 수치였다. 워킹트리가 멈춘 뒤 다시 재니 실패는
> `VW6` 하나였고, 그마저 원인은 제품이 아니라 프로브의 낡은 선택자였다.

### 깨진 모양 (실측)

```
72 len=280 "──────…──────Try "how do I log an err"   ← 가로선과 힌트가 한 줄에 섞임
74 len=254 "──────────────────────────────────"      ← 테두리가 화면(280)보다 좁다
```

원인은 하나다 — **TUI 가 아는 폭(254)과 xterm 이 가진 폭(280)이 다르다.**

### 깨진 모양 ② — 입력할 자리가 없다 (2026-09-02 추가)

```
76 len=280 "────────────…────────"   ← 테두리
77 len=280 "────────────…────────"   ← 테두리가 **바로 다음 줄**. ❯ 가 들어갈 행이 없다
78 len= 38 "  ⏵⏵ auto mode on (shift+tab to cycle)"
```

**폭은 완전히 정상이다** — 테두리 둘 다 cols 를 꽉 채우고, statusline 도 오른쪽 끝까지 가고,
오른쪽에 옛 프레임 잔상도 없다. 위의 폭 기준 항목(R1·R3)을 전부 통과한다. 그런데 깨진 것이다.
2026-09-02 에 사람 눈으로도, 이 문서의 판정 도구로도 "정상" 이라고 **두 번 오판했다**.

판별은 **테두리 두 줄의 행 간격**이다 — 정상이면 사이에 입력줄이 있으니 간격이 2 이상,
맞붙어 있으면(간격 1) 깨진 것이다. 스크린샷만 있을 때는 PIL 로 행 스캔해
`n≈전체폭` 인 행들의 y 간격을 재면 눈으로 안 보여도 확정된다(실측: y=59 / y=76, 행높이 17px).

> **정상 판정은 4개를 다 만족해야 한다** — ① statusline 이 오른쪽 끝까지 ② 테두리가 중간에서
> 안 끊김 ③ 오른쪽 잔상 없음 ④ **`❯` 입력줄이 자리를 차지함**. ①~③ 은 전부 폭 조건이라
> ④ 를 못 잡는다.

## 검증 방법

### 1) 격리된 테스트 인스턴스를 띄운다

실사용 Tabby 를 죽이지 않는다. `--user-data-dir` 이 Electron 싱글인스턴스 락을 갈라 주므로
별개 프로세스로 뜬다. `TABBY_CONFIG_DIRECTORY` 로 config 를 분리한다.

```cmd
set TABBY_CONFIG_DIRECTORY=<테스트 cfg 폴더>
start "" "%LOCALAPPDATA%\Programs\Tabby\Tabby.exe" --user-data-dir="<테스트 ud 폴더>" --remote-debugging-port=9222
```

**반드시 지킬 것 —**

- **실사용과 같은 권한으로 띄운다.** 승격된 셸에서 실행하면 권한이 상속돼 실사용과 조건이 달라진다.
  필요하면 `runas /trustlevel:0x20000 "<배치파일>"` 로 medium IL 로 내린다.
- **테스트 config 는 사용자 config 를 복사하지 않고 새로 쓴다.** 실측(2026-09-01): 옛 인스턴스의
  `ud` 폴더가 남아 있으면 `recoverTabs` 가 지난 탭을 되살려 config 를 고쳐도 옛 상태가 이어진다 —
  `ud` 를 새로 만들어야 한다 (`tools/test-instance.ps1` 이 매번 새로 만든다).
- 플러그인은 **그 인스턴스의 `ud\plugins\node_modules`** 에서 로드된다 — `test-instance.ps1` 이
  거기에 소스 트리로 junction 을 건다. 즉 테스트 인스턴스도 **작업 중인 소스**를 그대로 쓰고,
  `npm run build` 후 재기동하면 반영된다.
  (스크립트가 `NODE_PATH` 를 비우지 않으면 실사용 플러그인이 먼저 걸린다 — 아래 1-b 참고. 지금은 비운다.)
- 순정과 비교하려면 테스트 config 에 `agentDeck: { enabled: false }` 를 둔다. 그러면
  사이드바를 숨기고 `.content.main` 의 인라인 스타일을 걷어내므로 순정 레이아웃이 된다.

### 1-b) 자동 업데이트는 **진짜 npm 설치본**으로 따로 본다

```bash
node tools/regress-update.js          # U1~U7
node tools/regress-update.js --keep   # 인스턴스를 남긴다 (눈으로 볼 때)
```

위 1) 의 인스턴스로는 자동 업데이트를 못 본다 — 플러그인이 소스 junction 이라 개발 설치로 잡히고
(`canSelfUpdate` 가 막는다), npm 이 돌면 작업 중인 소스를 덮어쓴다. 그래서 이 러너는 격리 폴더에
**tgz 두 벌**(같은 코드, 버전만 다르게)을 말아 옛 것을 깔고 → 새 것으로 업데이트시킨다.

고정하는 것 — ① Tabby 가 **떠 있는 채로** 설치가 끝난다 ② 디스크 버전이 올라간다
③ 리로드 뒤 **세션 탭이 같은 pty 로** 돌아온다 ④ **Tabby pid 가 그대로다**(재시작이 아니다).

실측 2026-09-14: `7 ok, 0 fail`.

두 가지는 **러너가 알아서 한다** — 사람이 손댈 것은 없고, 왜 필요한지만 적어 둔다.

- **부모 환경의 `NODE_PATH`·`TABBY_PLUGINS` 를 비우고 Tabby 를 띄운다.** 회귀는 보통 Tabby 안의
  셸에서 도는데, 그 셸은 실사용 플러그인 폴더(`%APPDATA%` 아래 `tabby/plugins/node_modules`
  = 소스 junction)를 `NODE_PATH` 앞쪽에 물고 있다. Tabby 는 자기 경로를 그 **뒤**에 붙이므로
  `--user-data-dir` 을 줘도 node 는 실사용 쪽을 먼저 찾는다 — 격리 인스턴스인데 실사용
  플러그인이 뜬다(2026-09-14 실측). `regress-update.js`·`test-instance.ps1`·`run-all.ps1`
  셋 다 기동 직전에 이 두 변수를 비운다.
- **옛 버전은 tgz 를 따로 말아 만든다.** 설치본의 `package.json` 버전만 낮추는 방법은 안 통한다 —
  npm 은 `file:` 의존성을 경로로 판정해 "이미 그 tgz 다" 라며 폴더를 그대로 둔다
  (`added 1 package` 라고 찍고도 옛 버전 그대로).

### 3) pty 의 진짜 폭을 확인한다 (R1)

`pane.size` 는 **우리가 보낸 값을 적어 둔 것**이라 pty 의 실제 폭이 아니다. 셸에 직접 묻는다.

```
"PTYW=" + [Console]::WindowWidth + " PTYH=" + [Console]::WindowHeight
```

claude 가 돌고 있는 탭에서는 셸에 물을 수 없다. 그때는 **TUI 가 그린 테두리 길이**가 곧
TUI 가 아는 폭이므로 `ruleLens == [cols, cols]` 를 오라클로 쓴다.
