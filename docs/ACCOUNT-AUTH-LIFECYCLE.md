# 계정 인증 유지

## 저장과 갱신

- 최초 인증은 공식 브라우저 로그인으로 진행한다. ID/PWD로 로그인 화면을 자동 조작하지 않는다.
- `~/.agentdeck/accounts.json`의 `auth`는 Windows CurrentUser DPAPI 암호문이다. access token, refresh token, 만료 시각, 계정 식별 정보를 함께 보관한다.
- CLI 실행에 필요한 네이티브 인증 파일은 `~/.agentdeck/accounts/<key>/`에 따로 둔다. 이 파일은 CLI의 원래 형식이며 DPAPI 암호문과 별개다. 계정마다 홈과 인증 파일을 분리한다.
- 60초마다 인증 상태를 점검한다. 이메일이 같은 실행 환경의 새 인증정보를 우선 가져오고, 바뀐 경우에만 암호화 저장본을 갱신한다.
- Claude 토큰은 만료 5분 전부터 refresh token으로 갱신한다. 현재 CLI와 같은 토큰을 공유하면 그 원본 파일에 회전된 토큰을 저장한 뒤 계정 사본을 갱신한다. 요청 중 CLI가 토큰이나 계정을 바꾸면 그 새 파일을 덮어쓰지 않는다.
- 동일 계정의 동시 갱신은 합치고, 여러 Tabby 프로세스의 갱신은 파일 잠금으로 중복을 막는다. 갱신 실패 시 기존 인증을 지우지 않는다.
- Codex 인증 갱신은 공식 app-server의 `account/read`에 맡긴다. 갱신 결과는 같은 암호화 저장소에 반영한다.
- 실제 인증이 없거나 refresh token이 거부된 경우에만 사용자가 계정을 선택할 때 로그인 창을 연다. 백그라운드 작업은 로그인 창을 열지 않는다.

## 사용량 조회는 인증과 별개

- 현재 세션의 이메일과 provider를 확인한 후, 이미 수신한 5h/7d/모델별 사용량을 계정 카드에도 사용한다.
- 최근 정상 조회 결과를 계정별 `usage.json`에 저장한다. 네트워크 오류/429에서도 그 값을 유지하며 오래된 값에는 마지막 확인 시각을 표시한다.
- 429의 Retry-After를 저장하고 그 시간까지 같은 요청을 반복하지 않는다. 조회 제한은 로그아웃이나 재로그인 사유가 아니다.
- 계정 전환은 사용량 API 성공 여부로 판단하지 않고 인증 유지 경로로 판단한다.

## 커밋

실사용 계정 파일과 네이티브 인증 파일은 저장소 밖에 둔다. 계정 JSON을 스테이징할 때는 기존 검사기가 빈 필드만 허용하며 암호화된 인증값도 커밋하지 않는다.

## 검증

`test/accountSession.cjs`: 현재 인증 동기화, 공식 갱신 요청 형태, 토큰 회전, DPAPI 저장본 반영, 동시 갱신 합치기, 429 재시도 제한, 현재 세션 사용량 재사용, 오래된 값 표시, 타 계정 배제, 인증 실패와 일시 실패 분리.

`tools/probe-account-session.js`: 별도 계정 파일을 쓰는 격리 Tabby에서 사용량 API에 429를 주입하고, 현재 계정의 세 막대 유지 및 재로그인 없이 새 Claude 탭 실행을 확인한다. 실제 인증값은 출력하지 않는다.

실제 저장 계정에서도 브라우저 없이 Claude 토큰 갱신 및 DPAPI 저장본 일치를 확인했다. 갱신 endpoint와 public client ID는 설치된 공식 CLI에서 확인했다.
