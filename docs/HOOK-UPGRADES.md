# 훅 등록 갱신

## 훅 관리 화면

Claude / Codex 연동에 아래 작업을 제공한다. **어떤 작업도 다른 도구의 훅 전체를 초기화하지 않는다.** 삭제 대상은 등록 내용이며 패키지의 전달기 파일이나 다른 도구의 스크립트를 삭제하지 않는다.

| 버튼 | 범위 |
| --- | --- |
| 훅 전문 보기 | 기본 홈·존재하는 저장 계정 홈의 hooks와 statusLine 등록 전문, 판별 근거, 관리 기록을 읽기 전용으로 표시한다. 현재 설치된 AgentDeck 전달기 소스도 펼쳐서 볼 수 있다. |
| 관리 단락 제거 | 설치 기록의 단락과 현재 단락이 정확히 일치하는 항목만 제거한다. 단락을 수정했으면 보존한다. |
| 이력 기반 정리 | 배포 커밋에서 확인한 명령·경로·이벤트·옵션 조합과 일치하는 AgentDeck 항목을 정리한다. 혼합 그룹에서는 해당 항목만 제거한다. |
| AgentDeck 전체 초기화 | 관리 기록과 배포 이력으로 확인한 항목을 합쳐 정리한다. 출처 미확인·수정된 등록은 보존한다. 원본이 확인된 AgentDeck statusLine은 사용자 상태줄로 복원한다. |
| 설치 / 재적용 | 확인된 기존 항목을 최신 목록으로 교체하고 관리 기록을 갱신한다. 사용자 훅은 보존한다. 수정된 AgentDeck 등록 때문에 중복 실행 위험이 있으면 중단한다. |

각 버튼은 먼저 변경 미리보기를 연다. **변경 적용 → 확인 팝업의 적용**을 누르기 전에는 파일을 쓰지 않는다. 팝업 기본 선택은 취소다. 기존 파일별로 고유 이름의 백업을 남기고, 미리보기 이후 입력 파일이 바뀌면 적용을 거부한다. 여러 파일 저장 중 실패하면 완료한 변경을 되돌리며, 복구 중 외부 변경이 있으면 덮어쓰지 않고 백업 경로를 안내한다. Codex 신뢰 설정은 변경하지 않는다.

관리 단락은 JSON에 임의 필드를 넣는 방식이 아니다. CLI가 지원하는 독립 훅 그룹을 만들고, 같은 홈의 `.agentdeck-hook-registry.json`에 버전·제공자·안정적인 ID·정확한 그룹 내용·상태줄 원본을 기록한다. 앱 설정에서 재적용할 때뿐 아니라 최초 설치 및 저장 계정 준비 경로도 설치 기록을 남긴다. 기록 도입 전 항목은 이력 기반 정리로 다룬다.

이력 기반 정리는 클릭할 때 GitHub를 조회하거나 실행 코드를 다운로드하지 않는다. 조사·검증한 형태를 `src/hookCatalog.ts`에 포함해 배포한다. 현재 목록과 과거 목록은 분리해, 현재 이벤트가 폐기돼도 과거 형태가 사라지지 않게 한다. 신규 등록 형태를 배포할 때는 이 목록과 회귀 fixture를 함께 갱신한다.

`install.ps1 -Hooks`의 직접 쓰기는 중단했다. 플러그인 설치 후 앱의 전문 보기와 설치 / 재적용으로 안내한다. 구형 그룹 전체 삭제 구현은 실행되지 않는 이력 주석으로만 보관한다.

## 등록 이력과 관리 범위 (2026-10-30 최초 조사, 관리 화면 구현 전)

GitHub origin을 fetch한 뒤 로컬 전체 이력과 현재 등록 코드를 대조했다. 저장소 최초 커밋은 `a05e77f`(1.2.0)이므로 그 이전에 수동 설치한 형태까지 확인했다는 뜻은 아니다.

| 출처 | 확인된 등록 형태 | 최초 조사에서 발견한 문제 |
| --- | --- | --- |
| `install.ps1 -Hooks` (`a05e77f`부터 현재까지) | Claude 3개 이벤트, PowerShell, UserPromptSubmit의 `-PromptAsLabel` | 현재도 옛 형식을 생성한다. 기존 그룹의 JSON에 이름이 포함되면 그룹 전체를 제거하여 함께 든 사용자 훅도 사라질 수 있다. 이번 갱신은 `-PromptAsLabel` 형태를 인식하지 않는다. |
| `src/claudeHooks.ts` (`a05e77f`) | Claude 9개 이벤트, PowerShell, 상태/서브에이전트 인자 | 이름 부분 일치로 소유권을 판별한다. 설치/제거가 현재 PLAN만 순회하므로 앞으로 PLAN에서 빠진 이벤트의 구형 등록은 남을 수 있다. |
| `src/codexHooks.ts` (`a05e77f`) | Codex 7개 이벤트, PowerShell | 모든 이벤트를 순회하지만 이름 부분 일치 판별을 사용한다. |
| `7c43ecb` | 두 등록기의 PowerShell 명령을 Node 직접 실행으로 전환 | 새 등록 코드 변경만으로 외부 CLI 설정의 옛 등록이 교체되지는 않는다. |
| `656703b` | 저장 Claude 계정 홈에도 연동 반영, statusLine 원본을 홈별로 보존하고 `--inner` 지정 | 기본 홈뿐 아니라 저장 계정 홈도 조사해야 한다. statusLine은 기존 사용자 명령 복원이 필요한 별도 관리 대상이다. |
| `962f41d` | 지원하는 구형 PowerShell 등록을 찾아 갱신 안내, command만 교체 | 제한된 명령 변환이다. 전체 이력의 폐기 항목 정리나 통합 소유권 관리까지 구현한 것은 아니다. |

### 유지보수 규칙

- **현재 목록**: 안정적인 훅 ID, 제공자, 이벤트, 그룹 조건, 실행 명령, 옵션, 관리 규격 버전을 한 곳에서 정의한다. 앱 설치/해제, 계정 준비, 업그레이드는 같은 판별기를 사용한다. 설치 스크립트는 앱 관리 화면으로 안내한다.
- **과거 목록**: 실제 배포 이력에서 확인한 명령·인자·이벤트·옵션 조합, 도입/폐기 커밋, 대체 ID를 보존한다. 파일 이름이 닮았다는 이유만으로 소유권을 인정하지 않는다. 임의 경로의 복사본이나 사용자가 수정한 명령은 별도로 확인한다.
- **설치 기록**: AgentDeck 전용 저장소에 대상 설정 파일별로 마지막 적용 항목의 정확한 내용과 관리 버전을 기록한다. CLI 설정 JSON에 지원 여부가 확인되지 않은 전용 필드나 주석을 넣지 않는다.
- **대조와 정리**: 과거 설치 기록/알려진 구형 형태와 일치하는 항목만 갱신·폐기 대상으로 삼는다. 현재 목록에서 빠진 항목도 모든 이벤트에서 찾는다. 사용자 수정과 출처 불명 항목은 보존하고 안내한다. 단순히 오래 실행되지 않았다는 이유로 삭제하지 않는다.
- **적용**: 추가·교체·폐기·보존 대상을 먼저 계산하여 표시하고 백업 후 항목 단위로 반영한다. 사용자 훅이 섞인 그룹 전체를 지우지 않는다. statusLine은 소유권 확인 후 보관된 사용자 원본으로 복원한다. 파일 삭제는 등록 참조와 호환성 필요를 별도로 확인한다.
- **검증**: 알려진 과거 등록 형태별로 최신 목록 전환을 검증한다. 혼합 그룹, 사용자 변경, 중복, 폐기 이벤트, 변경된 설치 경로, 손상 파일, 중간 설정 변경, 재적용을 포함한다.

관리 화면 검증은 `test/hookManagement.cjs`와 격리 앱의 `tools/probe-hook-management.js`를 사용한다. 실제 사용자의 홈을 UI 프로브 대상으로 지정하지 않는다.

## 시작 시 구형 전달기 갱신 안내

AgentDeck 시작 시 기본 Claude/Codex 홈과 저장 계정 홈에서 구형 AgentDeck PowerShell 전달기 등록을 찾는다. 발견하면 기존 설치 안내를 닫았던 사용자에게도 **기존 훅 갱신** 안내를 표시한다. 단순히 앱 버전이 바뀔 때마다 표시하지는 않는다.

- **갱신한다**: 설정 원문을 `.agentdeck-hook-upgrade-backup`에 백업하고 AgentDeck 전달기 명령만 Node 직접 실행으로 교체한다. 사용자 훅, matcher, timeout, async, statusLine과 다른 설정은 보존한다.
- **나중에**: 설정을 쓰지 않는다. 다음 앱 시작 시 다시 확인한다.
- 현재 방식이면 안내하지 않는다. 훅이 없는 CLI에 자동으로 새 훅을 설치하지 않는다.
- 별도 `claude-compat` 훅처럼 이름만 같은 다른 연동은 교체하지 않는다. 사용자 정의 명령 체인도 그대로 둔다.
- 안내가 열린 동안 설정이 바뀌면 저장하지 않고 오류를 알린다. Codex의 신뢰 상태는 수정하지 않는다. 실행 중인 CLI는 훅 재로드나 재시작이 필요할 수 있다.

이번 마이그레이션은 PowerShell → Node 직접 실행에 한정된다. 앞으로 등록 구조가 다시 바뀌면 해당 변경을 판별하고 옮기는 마이그레이션을 추가해야 한다. 등록 명령과 경로가 그대로인 훅 구현 변경은 패키지 파일 업데이트로 반영된다.

`node test/hookUpgrade.cjs`는 기본 교체, 보존, 멱등성, 설정 변경 충돌과 손상 JSON을 검사한다. `tools/probe-hook-upgrade.js`는 `usage-refresh-ui` 전용 격리 앱에서 거절·실제 갱신 팝업·백업·재안내 방지를 검사한다. 실사용 설정 대상으로 이 프로브를 실행하지 않는다.
