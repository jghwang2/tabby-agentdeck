# 새 계정 로그인 연결 종료 수정

## 원인

실사용 Tabby 프로세스가 물려받은 PATH에는 설치된 Codex 위치가 없었다. 기존 코드는 그 PATH만 검색한 뒤 `spawn('codex', ...)`로 실행했고, 실행 실패도 일반 연결 종료로 표시했다. 개발 셸에서 띄운 이전 격리 앱은 새 PATH를 물려받아 해당 문제를 재현하지 못했다.

## 수정과 검증

- Windows의 현재 사용자·시스템 PATH를 추가로 조회해 CLI를 찾고 자식 프로세스에도 합쳐진 PATH를 제공한다. 조회는 1분간 캐시하고 5초 제한을 둔다. 인증정보는 조회 명령에 포함하지 않는다.
- `test/accountCliRoots.cjs`: 오래된 Tabby PATH, 새로 등록된 CLI 경로, 중복 제거, 조회 캐시, 실행 중 환경 변경을 검증했다.
- 전체 `npm test` 통과. 새 경로 회귀 단위 검사도 별도 통과했으며 `test:accounts`에 연결했다.
- 실제 Tabby 프로세스의 환경을 메모리에서 읽어 별도 테스트 프로세스에 전달했다. 환경 전체를 파일이나 출력에 저장하지 않았다.
- 그 환경에서 인증 없는 임시 계정으로 실제 Codex의 `account/login/start`가 공식 로그인 주소를 반환하고 취소가 처리됨을 확인했다.
- 같은 환경·동일 테스트로 이전 커밋 `83ae283`을 실행하면 `connectionClosed: true`, `freshUnauthenticatedLoginReachedOfficialBrowser: false`가 나왔다. 수정본은 공식 로그인 주소 도달과 취소 처리가 모두 성공했다.
- 같은 환경으로 격리 Tabby를 시작하고 `tools/probe-account-login-start.js`를 실행했다. 공식 브라우저 호출, 브라우저 실행 실패 시 기존 세션 보존, 재시도 활성화, 오류 안내 4개를 모두 통과했다.
- 실제 브라우저 로그인 완료와 추가 인증은 자동 검증하지 않았다. 테스트에서 브라우저 호출을 의도적으로 실패시켰으므로 로그인 완료로 보고하지 않는다.
- 검증 빌드 SHA-256: `BD2CB6BB721055993EE8A1B9F0A767ACA9B901F40DA3FEF47A212B279F0C0EA5`.
- 전체 회귀 최초 실행은 166개 중 140 통과·3 실패·23 제외였다. 실사용 환경에 Git 경로도 없어 CW4·CW7·R29가 실패했다. 계정 로그인 검증은 해당 원래 환경에서 통과했으며, Git 관련 검사는 Git을 사용할 수 있는 새 격리 환경에서 재검증했다.
- 재검증: `probe-cwd.js` 8개 전부 통과, 원래 러너의 창 크기·초기 탭 조건을 맞춘 새 앱의 `probe-all.js`는 31 통과·실패 0·8 제외. 최초 실패 3개가 모두 통과했다. 재사용한 앱의 삭제된 임시 폴더나 기본 창 크기로 실행한 중간 재검사 결과는 최종 판정으로 사용하지 않았다.
- 유출 검사: 현재 등록 계정 4개와 전체 인덱스 262개 파일을 대조해 통과.
- 실사용 핫리로드: `2026-09-21T10:44:06.126Z reload go reason=dev:build tabs=4`, `2026-09-21T10:44:10.091Z reload restored tabs=4 dead=0 ms=2239`. 동일 검증 빌드로 탭 4개가 모두 복구됐다.

이 수정은 CLI 실행 경로 발견을 수정하며, 프로세스를 유지하는 계정 전환 구조 변경은 아니다.
